# tenchat-parser

Парсер постов [TenChat](https://tenchat.ru/) по списку хештегов. Для каждого поста собирает заголовок, автора, дату публикации, ссылку и количество просмотров; результат сохраняется в CSV с автоматической дедупликацией по URL и, опционально, фильтрацией по дате.

## Что умеет

Парсер работает в два шага:

1. **Сбор ссылок.** Проходит по страницам `https://tenchat.ru/hashtag/{slug}` из встроенного списка и с каждой собирает 20 постов верхней ленты (вкладка «Топ» на стороне TenChat; другие вкладки в SSR-разметке недоступны). Для каждого поста извлекает `title`, `author`, `url`, `views`, `hashtag`.
2. **Дозагрузка даты и фильтрация.** Для каждой собранной ссылки открывает `/media/{slug}`, вытаскивает `datePublished` из блока JSON-LD (Schema.org BlogPosting), кладёт его в поле `date` и отбрасывает посты, опубликованные раньше `--cutoff-date` (по умолчанию `2026-04-14`). Шаг 2 можно отключить флагом `--no-enrich`.

Между всеми HTTP-запросами делается случайная пауза 2–3 секунды. Дубли посты (если один и тот же пост попал в несколько хештегов) удерживаются один раз — ключ дедупликации `url`, в колонке `hashtag` остаётся тот тег, под которым пост встретился впервые.

## Требования

- Python 3.9+
- `requests`, `beautifulsoup4`

## Установка

```bash
git clone https://github.com/DmitryChuchulin/tenchat-parser.git
cd tenchat-parser
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

Полный прогон по списку `HASHTAGS` с фильтром по умолчанию (`2026-04-14`):

```bash
python3 tenchat_parser.py
```

С произвольным cutoff:

```bash
python3 tenchat_parser.py --cutoff-date 2026-04-07
```

По произвольному подмножеству хештегов (удобно для отладки, чтобы не ждать полный прогон):

```bash
python3 tenchat_parser.py --tags razrabotka biznes cto
```

Без Шага 2 — только собрать ссылки, без дат и без фильтра:

```bash
python3 tenchat_parser.py --no-enrich
```

В stdout идёт прогресс. Сначала — Шаг 1:

```
=== Шаг 1: сбор ссылок по 30 тегам ===
[1/30] #razrabotka → https://tenchat.ru/hashtag/razrabotka
    постов на странице: 20, новых: 20
...
Уникальных постов после Шага 1: 515
```

Затем — Шаг 2, со знаком `+` для прошедших cutoff и `-` для отфильтрованных:

```
=== Шаг 2: дозагрузка даты, фильтр cutoff=2026-04-14 ===
  [1/515] + 2026-04-18  https://tenchat.ru/media/5228095-...
  [2/515] - 2025-06-02  https://tenchat.ru/media/3386944-...
  ...
После фильтрации по дате: 83 из 515
```

По окончании появится файл вида `posts_20260421_163238.csv`.

### Время прогона

Полный прогон на 30 тегах занимает **~30 минут**: Шаг 1 отрабатывает за ~2 минуты, а Шаг 2 — это ещё по запросу на каждый из ~500 собранных постов с паузой 2–3 с. Для итераций по селекторам/парсингу используйте `--tags` с 2–3 тегами либо `--no-enrich`.

## Настройка

Параметры заданы константами в начале `tenchat_parser.py`:

| Константа              | Назначение                                                 |
|------------------------|------------------------------------------------------------|
| `HASHTAGS`             | Список хештегов для обхода (slug'и — см. ниже)             |
| `MIN_DELAY`            | Минимальная пауза между запросами, секунд                  |
| `MAX_DELAY`            | Максимальная пауза между запросами, секунд                 |
| `TIMEOUT`              | Таймаут HTTP-запроса, секунд                               |
| `CUTOFF_DATE_DEFAULT`  | Дата cutoff по умолчанию (перебивается флагом `--cutoff-date`) |
| `HEADERS`              | HTTP-заголовки (User-Agent, Accept-Language и т. п.)       |
| `CSV_FIELDS`           | Порядок колонок в выгрузке                                 |

### Про slug'и хештегов

TenChat отвечает **404** на URL вида `/hashtag/{кириллица}`; нужны транслитерированные slug'и. Причём правило транслитерации у TenChat нестандартное и местами неочевидное: `сайтов` → `saytov` (а не `sajtov`), `мобильное` → `mobilnoye` (с `y` перед `e`), `проектами` → `proyektami` (аналогично). Если нужно добавить новый тег, проще всего найти любой пост с этим хештегом на сайте и скопировать slug из ссылки вида `tenchat.ru/hashtag/{slug}`.

## Формат CSV

| Поле      | Описание                                                                               |
|-----------|----------------------------------------------------------------------------------------|
| `title`   | Заголовок поста                                                                        |
| `author`  | Имя автора                                                                             |
| `date`    | ISO-8601 `datePublished` из JSON-LD (`2026-04-18T12:14:27.739305+03:00`). Пусто, если запускали с `--no-enrich` |
| `url`     | Абсолютная ссылка на пост вида `https://tenchat.ru/media/{slug}`                       |
| `views`   | Счётчик просмотров в исходном формате TenChat: `"1234"`, `"2.7K"`, `"185.3K"` и т. п.  |
| `hashtag` | Первый хештег, на чьей странице пост был обнаружен                                     |

## Как устроен парсинг

### Шаг 1: сбор карточек со страницы хештега

TenChat — это Nuxt-приложение (не Next.js). Страница хештега содержит `<script id="__NUXT_DATA__">` с состоянием, но данные сериализованы в «плоский» массив с числовыми референсами между индексами, а «детальный» слот поста (`hashtag-guest-detailed-{slug}`) у неавторизованного пользователя приходит как `null` — т. е. вытащить структурированные данные постов из этого payload'а нетривиально.

Зато SSR-разметка карточек ленты содержит всё нужное: каждый пост — это `<a href="/media/{slug}">`, внутри которого текстовыми нодами расположены заголовок, имя автора, его должность и счётчик просмотров. Парсер обходит эти якоря, собирает `stripped_strings`, берёт первую текстовую ноду как `title`, вторую как `author`, а последнюю, подходящую под регексп `VIEWS_RE` — как `views`. Если в будущем TenChat поменяет раскладку карточек, править нужно функцию `extract_posts` (и, возможно, `VIEWS_RE`) в `tenchat_parser.py`.

### Шаг 2: дата с индивидуальной страницы поста

Страница отдельного поста содержит Schema.org разметку в виде `<script type="application/ld+json">` с объектом `BlogPosting`, у которого есть поле `datePublished` в ISO-8601 (`2026-04-18T12:14:27.739305+03:00`). Парсер находит JSON-LD-блоки, парсит их, достаёт первый объект с `datePublished` — это и есть дата публикации. Логика лежит в функции `extract_date_published`.

### Почему не API напрямую

На TenChat есть внутренняя ручка `POST /gostinder/api/web/hashtag-listing/{slug}/posts`, которой пользуется клиентский JS для переключения вкладок «Топ» / «Недавние». Мы её обнаружили, но без DevTools не смогли подобрать формат тела запроса: на `{}` и стандартные варианты (`{page,size}`, `{limit,offset}`, `{pageable:{…}}` и т. д.) ручка возвращает `500 INTERNAL_ERROR` либо `400 UNSUPPORTED`. Query-параметры `?tab=recent`, `?sort=new`, `?order=date` на HTML-странице игнорируются сервером (все возвращают идентичный top-feed). Поэтому фильтрация по дате реализована на клиенте через обход страниц постов. Если удастся перехватить реальный POST-payload в браузере, Шаг 2 можно будет заменить одним запросом на тег.
